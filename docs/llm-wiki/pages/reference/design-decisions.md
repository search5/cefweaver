# 설계 결정 기록

중요한 결정과 그 이유입니다. 사람이 직접 정한 것은 "결정자: 사용자"로 표시합니다. 그 밖은 구현 중에 근거를 확인하고 정한 것입니다. 결정이 바뀌면 이 페이지를 고치고 이전 결정과 바뀐 이유를 남깁니다.

## 빌드와 패키징

| 결정 | 이유 | 결정자 |
| --- | --- | --- |
| `setup.py` 없이 `pyproject.toml`의 `ext-modules`로 Cython 확장을 선언 | Poetry에서 setuptools 백엔드와 uv로 바꾼 이유가 정적 선언만으로 Cython을 빌드하기 위해서였습니다. | 사용자 |
| 사전 준비(CEF 확보, 네이티브 빌드)와 `uv build`를 분리 | 확장을 빌드할 때 CEF 헤더와 컴파일된 라이브러리가 이미 있어야 합니다. 앞 두 단계는 사전, Cython과 패키징은 `uv build` 시점입니다. | 사용자 |
| 확정된 CEF를 `build/native/cef`에 고정 경로로 연결 | 정적 설정은 환경변수를 경로에 쓸 수 없습니다. 고정 경로가 있으면 소스 빌드와 prebuilt의 차이가 이후 단계에 드러나지 않습니다. 대안(컴파일러 환경변수)은 사용자 부담이 큽니다. | 사용자(선택지 1) |
| 기본 CEF 버전을 154.0.34로 상향 | "최신 버전으로 가자". 래퍼 코드는 수정 없이 빌드되었습니다. | 사용자 |
| `--cef-version`은 전체 이름만, 접두사 해석 없음. `--list-versions`는 전체 이름 출력 | 접두사는 어떤 빌드가 선택될지 모호합니다(120 하나에 빌드 15개). 필터는 목록을 걸러 보는 용도에만 씁니다. 인덱스는 하루 캐시합니다. | 사용자 |
| CEF 확보에 소스 빌드를 포함(`--build-cef`) | cefpython의 `--build-cef`와 같은 기능이 필요합니다. 코드는 `libcef.so`를 컴파일하지 않으므로 소스 빌드는 `automate-git.py`를 감쌉니다. | 사용자 |
| macOS는 지원하지 않고 구성 단계에서 명확한 오류 | 프레임워크 로딩, helper 번들, Cocoa 메시지 루프 결합이 필요한데 검증할 환경이 없습니다. 검증 없이 쓰면 동작하지 않는 코드가 남습니다. | 사용자(선택지 1) |
| clang-format 내려받기를 옵션(기본 꺼짐)으로 | 빌드에 필요하지 않고 Python 3.14에서 gsutil이 오류로 구성을 중단시켰습니다. | 구현 중 판단 |
| `CEF_ROOT`를 CMake 캐시에 저장하지 않음 | 옛 버전이 조용히 고정되는 결함([실험으로 확인한 사실](verified-findings.md)). | 구현 중 판단 |
| 런타임을 `cefweaver/`에 복사(스테이징)하고 `libcef.so` 복사본만 strip | 1.45GB를 272MB로 줄입니다. 원본 배포본은 건드리지 않습니다. | 구현 중 판단 |
| 서브프로세스를 패키지 디렉터리 바로 아래 실행 파일로 | `libcef.so`와 리소스를 공유해 두 번 복사하지 않습니다. | 구현 중 판단 |
| `uv build --wheel`을 표준으로, `MANIFEST.in`으로 sdist에서 런타임 제외 | sdist만으로는 wheel을 만들 수 없고, 런타임을 넣으면 147MB가 됩니다. | 구현 중 판단 |

## 바인딩

| 결정 | 이유 | 결정자 |
| --- | --- | --- |
| 바인딩을 손으로 쓰지 않고 CEF 헤더에서 **생성** | 클래스 185개, 가상 메서드 약 1,440개. 10여 개 메서드의 래퍼에서도 결함이 5건 넘게 나왔습니다([API 중계 규모와 생성기 선택](../analyses/api-relay-scale.md)). | 사용자 |
| Python API는 **PEP 8** 이름 | `Cef` 접두사를 떼고 snake_case, 예약어는 밑줄(`continue_`). | 사용자 |
| 1단계는 **리소스 핸들러** | 가짜 URL로 시험하는 java-cef의 `addResource`에 해당합니다. | 사용자 |
| **나중에 모든 타입을 다룰 수 있게** | 타입 종류를 확장하는 구조(`typesys.py`)와 미지원 사유를 남기는 보고서. | 사용자 |
| CEF의 `cef_parser.py`를 `tools/gen/vendor/`에 복사 | 배포본에는 파서가 없습니다(헤더만 있음). 저장소에 두면 CEF 소스 없이 생성할 수 있습니다. 출처 커밋과 라이선스를 함께 보관합니다. | 구현 중 판단 |
| 입력은 **배포본의 헤더**, 생성 결과는 **커밋** | 쓰는 `libcef`와 항상 같은 버전이고, 패키지를 빌드하는 사람이 생성기를 실행하지 않아도 됩니다. | 구현 중 판단 |
| 핸들러의 출력 인자는 반환값으로, `void*`+크기는 `memoryview`로 | Python다운 시그니처를 위해서입니다. 반환값이 먼저이고 하나면 그대로, 둘 이상이면 튜플. | 구현 중 판단 |
| 재정의한 메서드만 함수 포인터 표에 넣고 나머지는 CEF 기반 클래스 동작 | 기본 동작을 흉내 내지 않고 CEF가 정한 대로 둡니다. 순수 가상은 기본값을 반환합니다. | 구현 중 판단 |
| JS 바인딩은 **이름만** 렌더러로 보냄 | `std::string`을 품은 객체를 원시 복사하면 다른 프로세스에서 무효였습니다([실험으로 확인한 사실](verified-findings.md)). | 구현 중 판단 |
| 모듈을 불러올 때 `cef_api_hash()` 호출 | 초기화 전에 `Request.create()`가 프로세스를 죽이지 않게 합니다. | 구현 중 판단 |
| 손으로 쓴 `CefApp`은 유지하고 `add_resource`는 생성된 API만으로 구현 | 생성기가 실제로 쓸 만한지 보여 주는 첫 사용처입니다. CEF의 `CefApp`(핸들러)은 생성하면 `App`이 되어 이름이 겹치지 않습니다. | 구현 중 판단 |
| 다음 단계로 `CefClient` 위임 구조를 값 타입 구조체보다 먼저 | 핸들러가 가장 흔한 사용 경로이고, 핸들러를 쓸 수 있어야 어느 구조체가 필요한지 알 수 있기 때문입니다. | 사용자(선택), 시험 우선(TDD)도 사용자 |
| 클라이언트는 **래퍼가 고정한 `CefWrapperClientHandler`** 하나이고, 사용자의 `Client`는 그 뒤에서 이벤트를 받음 | 래퍼가 스스로 해야 하는 일(브라우저 목록, 준비 플래그, 오류 페이지, 창 제목)을 사용자가 지우지 못하게 합니다. 사용자의 클라이언트를 CEF에 곧바로 넘기면 `is_ready_to_execute_javascript`와 종료 절차가 깨집니다. | 구현 중 판단 |
| 래퍼의 핸들러가 **생성된 전달 클래스(`Cw<이름>Forward`)를 상속**해서 사용자 핸들러로 넘김 | 모든 메서드를 손으로 전달하면 핸들러를 추가할 때마다 늘어납니다. 생성하면 새 핸들러도 같은 방식으로 열립니다. 참조 계수를 구현하지 않아야 한 객체가 여러 핸들러를 상속합니다. | 구현 중 판단 |
| 이벤트 순서: 생성, 시작, 상태 변화, 종료, 제목은 **래퍼 먼저**, 닫기 전(`DoClose`, `OnBeforeClose`)과 로드 오류는 **사용자 먼저** | 사용자가 브라우저가 등록된 상태에서 생성을 보고, 목록에서 빠지기 전에 닫힘을 보며, 래퍼가 페이지를 바꾸기 전에 오류를 알게 합니다. `do_close`가 `True`이면 닫기를 막습니다. | 구현 중 판단 |
| 사용자의 `get_..._handler()`를 CEF가 물을 때마다 부름(한 번에 저장하지 않음) | CEF의 `CefClient` 의미를 그대로 따릅니다. 비용은 측정하지 않았습니다. | 구현 중 판단 |
| `set_client()`는 `initialize()` 전에만 | 브라우저를 만들 때 클라이언트가 정해져야 합니다. 이후에는 `RuntimeError`. | 구현 중 판단 |

## 서브프로세스와 런타임

| 결정 | 이유 |
| --- | --- |
| `cefsubprocess`의 `main`에 `no_stack_protector` | 종료 때의 `stack smashing`을 없앱니다([실험으로 확인한 사실](verified-findings.md) F3). |
| `resources_dir_path`를 기본으로 설정하지 않음 | 효과가 없음을 확인했습니다. 런타임 파일을 `libcef.so`와 같은 디렉터리에 둡니다(F1). 처음에 기본 설정을 넣었다가 뺐습니다. |
| 샌드박스를 쓰지 않고(`no_sandbox`) `chrome-sandbox`를 스테이징하지 않음 | 원래 래퍼의 설정을 유지했습니다. |
| 외부 메시지 펌프(`multi_threaded_message_loop` 끔) | 원래 래퍼의 선택을 유지했습니다. 사용자 스레드가 UI 스레드가 됩니다. |
